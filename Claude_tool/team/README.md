# team/ — AI同士の連絡ルール

このプロジェクトでは、複数のAI(Claude・Muse など)が**同時に**作業する。
このフォルダは、互いの状態を知り、依頼・質問をやり取りするための場所。
**参加するAIはすべて、このルールに従う。**

## 名前

ファイル名や記入欄では、次の名前を使う。

| 名前 | 誰か |
|---|---|
| `claude` | Claude |
| `muse` | Meta の Muse AI |
| `user` | 人間(このプロジェクトの持ち主) |
| `any` | 宛先を決めない(手の空いたAIが取る) |

同じ種類のAIを同時に2つ以上動かすときは、`claude-2` のように番号を付けて区別し、`status/` にもその名前のファイルを作る。

状態ファイルの名前は必ず `<名前>.status.md` にする。`claude.md` にすると、macOS では大文字小文字が区別されないため `CLAUDE.md`(プロジェクトの指示ファイル)として読み込まれてしまう。

## 構成

```
team/
  README.md        このファイル
  status/
    <名前>.status.md  各AIの状態。書くのは本人だけ。他のAIのファイルは読むだけ
  tasks/
    _TEMPLATE.md   依頼ファイルの書式
    open/          未着手の依頼・質問
    doing/         作業中の依頼
    done/          完了した依頼(履歴)
```

## いつ確認するか

次のタイミングで、**下の「確認の手順」を毎回行う**。

1. 作業を始めるとき
2. 1つの作業を終えたとき(次に取りかかる前)
3. ユーザーに報告する前

## 確認の手順

1. `tasks/open/` で、ファイル名が `to-自分の名前` または `to-any` のものを探す。あれば「依頼を受ける」に従う
2. 他のAIの `status/<名前>.status.md` を読み、相手が何をしていて、どのファイルを編集中かを知る
3. 自分の `status/<自分の名前>.status.md` を、今の状態に書き換える

## 依頼を出す

1. `tasks/_TEMPLATE.md` をコピーし、`tasks/open/` に次の名前で置く
   `YYYYMMDD-HHMM_to-<宛先>_<件名>.md` (例: `20261107-1430_to-claude_ログイン画面のエラー調査.md`)
2. 「内容」には、何をしてほしいか(何を知りたいか)と、**何をもって完了とするか**を書く
3. 返事を待つ間は、その依頼の結果がなくてもできる作業を進める

## 依頼を受ける

1. **ファイルを `tasks/open/` から `tasks/doing/` へ移す。** これが「自分が引き受けた」という宣言になる
   - 移動に失敗した(ファイルが見つからない)ときは、他のAIが先に取ったということ。その依頼には手を出さない
2. 移せたら、ファイルの「担当」に自分の名前を書く
3. 依頼者に確認したいことが出てきたら、「やり取り」に質問を追記し、ファイル名の宛先を依頼者に変えて `tasks/open/` に戻す
   (例: `..._to-claude_...` → `..._to-muse_...`)。依頼者が答えたら、宛先を戻して `open/` に置き直す
4. 終わったら「結果」に、何をしたか・変えたファイル・どう確かめたかを書き、`tasks/done/` へ移す
5. 自分では無理だと分かったら、「やり取り」に理由を書き、`担当` を空にして `tasks/open/` に戻す

## ファイルを編集するとき(同時作業での衝突を防ぐ)

- 編集を始める前に、他のAIの `status/` の「編集中のファイル」を見る。そこに載っているファイルは編集しない。変更が必要なら、そのAI宛てに依頼を出す
- 編集を始めるときは、先に自分の `status/` の「編集中のファイル」にそのファイルを書いてから編集する。終わったら消す
- 他のAIの `status/` ファイルや、他のAIが担当している `doing/` の依頼ファイルの中身は書き換えない(「やり取り」への追記だけはよい)

## ここに書かないもの

- パスワード・APIキー・個人情報
- 長く残す知識(はまった問題・決まった方針)。それはプロジェクトの `LESSONS.md` などに書く。`tasks/` は済んだら流れていく場所なので、ここに書いた知識は埋もれる

## 困ったとき

- 依頼に長く返事がない、ルールが合わない、AI同士で判断が食い違う → `to-user` で依頼を出し、ユーザーに判断を仰ぐ
- `done/` が増えて邪魔になったら、ユーザーが古いものを整理する(AIは `done/` のファイルを削除しない)
